# Архитектурная записка: parent-only orchestration

Дата: 2026-09-16

Родительский DSH-агент остаётся единственным оркестратором. Workflow не создаёт отдельный Planner: план передаётся родителем через `task_orchestrate` или строится минимально и детерминированно плагином. Это сокращает один model call и не требует копирования истории родителя в отдельный планировщик.

Reviewer не является постоянным управляющим процессом. Если проверка нужна, родитель добавляет задачу с ролью `reviewer` в общий предел шести workers. Результат этой задачи преобразуется в review-поля общего ответа.

Приёмка контекста использует дискретные уровни 8K, 16K, 24K, 32K, 49K, 65K, 81K и 96K; общий профильный бюджет остаётся 98 304 токена. Стоимость задачи включает контекст, резерв ответа, резерв безопасности и общий запас. Перед эскалацией предыдущий отчёт компактизируется до фактов, доказательств, тестов, блокеров и следующих шагов; затем уровень повышается только после структурированного `NEED_MORE_CONTEXT`, максимум две повторные попытки. NInfer остаётся источником истины для фактических токенов, KV-размещения и восстановления.

Очередь поддерживает разные ceilings concurrency по размеру запроса. На RTX 3090 с сохранёнными Vision, MTP, INT8 KV и 96K NInfer фактически устойчивы только два активных потока: запуск с тремя и шестью потоками не прошёл резервирование runtime-памяти. Поэтому текущий профиль честно ограничен двумя, а значения 3–6 остаются возможностью кода для отдельного GPU-профиля после benchmark.

Статус задачи и размещение вычислительного кеша разделены. `PARKED` не выставляется по факту ожидания; этот статус допустим только после отдельного подтверждения сохранённого состояния. После перезапуска Responses id может быть недействителен, поэтому история восстанавливается из DSH, а потерянный KV и повторный prefill должны отражаться в отчёте.
