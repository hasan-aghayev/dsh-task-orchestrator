# Архитектурная записка: parent-only orchestration

Дата: 2026-09-16

Родительский DSH-агент остаётся единственным оркестратором. Workflow не создаёт отдельный Planner: план передаётся родителем через `task_orchestrate` или строится минимально и детерминированно плагином. Это сокращает один model call и не требует копирования истории родителя в отдельный планировщик.

Reviewer не является постоянным управляющим процессом. Если проверка нужна, родитель добавляет задачу с ролью `reviewer` в общий предел шести workers. Результат этой задачи преобразуется в review-поля общего ответа.

Приёмка контекста использует дискретные уровни 8K, 16K, 24K, 32K, 49K и 65K. Стоимость задачи включает контекст, резерв ответа, резерв безопасности и общий запас. Уровень повышается только после структурированного `NEED_MORE_CONTEXT`; максимум две повторные попытки. NInfer остаётся источником истины для фактических токенов, KV-размещения и восстановления.

Статус задачи и размещение вычислительного кеша разделены. `PARKED` не выставляется по факту ожидания; этот статус допустим только после отдельного подтверждения сохранённого состояния. После перезапуска Responses id может быть недействителен, поэтому история восстанавливается из DSH, а потерянный KV и повторный prefill должны отражаться в отчёте.
